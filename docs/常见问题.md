## 安装与运行

### 为什么必须单 Worker？

Telegram Polling、调度器、整理互斥与 STRM 状态均包含进程内单例。多个 Worker 会重复执行任务或争抢 Bot 更新。请保持一个 MediaFlux 进程、一个 Uvicorn Worker。

### Docker 启动后提示目录不可写？

容器使用 UID/GID `10001:10001`。`db/`、STRM 目录和媒体目标目录必须可写；本地整理的来源目录还需删除权限。推荐 ACL，而不是随意改变 qB 文件属主：

```bash
sudo setfacl -R -m u:10001:rwX /srv/mediaflux/downloads /srv/mediaflux/library
sudo setfacl -R -d -m u:10001:rwX /srv/mediaflux/downloads /srv/mediaflux/library
```

### 保存设置后是否需要重启？

业务配置通常即时生效，Telegram Token 会触发 Polling 热重启。网络发布配置不在 Web 设置页维护：Docker 容器内部固定监听 `0.0.0.0:1258`，宿主机发布地址与端口由 `.env` 的 `MEDIAFLUX_PUBLISH_HOST`、`WEB_PORT` 控制，修改后执行 `docker compose up -d`。`WEB_SECRET_KEY` 等启动配置变更也需要重新创建或重启容器。

### 数据如何备份？

源码模式执行 `python mediaflux.py backup create --reason manual`，再用 `python mediaflux.py backup verify <zip>` 校验。该备份使用 SQLite 在线快照并包含数据库、`user.env` 与光鸭 Token；恢复前必须停止服务，再执行 `python mediaflux.py backup restore <zip>`。Docker 整机迁移还应保留 Compose 的 `.env`、挂载目录和反向代理配置。STRM 可重建，但大库建议另行归档。数据库结构升级前还会自动创建迁移前备份，失败时拒绝继续迁移。

## 本地媒体整理

### Docker 中为什么看不到宿主机目录？

Web 中看到的是容器文件系统。先把宿主机目录挂载到容器，例如 `/srv/downloads:/media/downloads`，再把 `LOCAL_MEDIA_BROWSE_ROOTS` 设置为 `/media/downloads,/media/library`。

### 本地整理是复制还是移动？

是移动。同文件系统尽量原子移动；跨文件系统先写目标临时文件并校验，成功后删除源文件。请为目标磁盘预留至少一个待移动文件大小的临时空间。

### 为什么整理后源空目录没有删除？

“执行后清理空目录”同时适用于光鸭和本地，但有安全条件：

- 来源根目录永不删除。
- 任务失败、可能部分执行或需保留恢复现场时跳过清理。
- 本地只删除确认空目录；光鸭通过受保护的回收站删除语义处理。
- 含未知/未处理文件的目录不是空目录。

### 系统会删除哪些垃圾文件？

只清理高置信度垃圾：零字节文件、明显广告/说明文本、临时残留、系统索引、明确 sample/proof 等。不会无条件删除 `.nfo`、字幕、图片、字体、章节或未知内容。

### qB 路径映射怎么填？

若 qB 容器路径是 `/downloads/completed`，MediaFlux 同一宿主目录挂载为 `/media/downloads/completed`：

- qB 路径前缀：`/downloads/completed`
- 本地来源根目录：`/media/downloads/completed`

## 识别与整理

### 为什么明显的剧集仍要求人工确认？

常见原因包括：标题清洗后仍有歧义、季号/集号超出 TMDB 记录范围、多个候选相近、同目录确有不同媒体或目标冲突。系统优先避免误入库，不会只凭 100% 文本相似度绕过剧集范围检查。

处理顺序：

1. 在日志详情查看跳过原因和候选评分。
2. 使用刮削实验室验证文件名与父目录上下文。
3. 手动选择正确 TMDB 候选、季号和集号。
4. 对固定命名源建立 TMDB 映射锁或强制匹配规则。

### AI、豆瓣、Bangumi 会直接决定目标吗？

不会。它们只在普通 TMDB 识别失败时提供标题/候选线索，最终仍由 TMDB 和严格阈值复核。AI 不能绕过人工确认和写操作安全检查。

### OVA、Extra、Specials 如何处理？

可确认的 OVA/特别篇进入 `Specials` 并使用 `S00E..`。`Extra` 中无法映射到 TMDB 特别篇的内容会保留或进入人工确认，不随意编造集号。

### 为什么出现 `(1)`、重复目录或 `.backup-*`？

通常表示旧版本任务中断、目标已存在或历史冲突回退。当前冲突处理以媒体身份、季集和版本策略为准；不要直接批量删除。先在日志中核对操作步骤，再使用回退/重新整理。`.backup-*` 是事务恢复痕迹，确认目标有效后再清理。

### ffprobe 必须安装吗？

Docker 官方镜像已经内置 ffprobe；Python 源码部署则需要系统自行安装 FFmpeg。整理会固定尝试媒体规格补全：本地文件直接调用 ffprobe，光鸭文件通过实时 signedURL/直链调用 ffprobe，并缓存成功结果。程序按 `MEDIAFLUX_FFPROBE`、系统 `PATH` 查找；找不到、超时或解析失败时只回退到文件名规格，不会阻断整理。

## 光鸭与 STRM

### 光鸭删除后，重新发送同一磁力为什么提示已存在？

下载请求记录与云盘文件是不同状态。待处理页可重新投递到光鸭/qB/两者；系统会按目标独立补投。若请求已无实际资源，可清除待处理记录后重新提交。

### 离线任务为什么提示“解析器标记为排除”？

种子/磁力中没有符合允许扩展名和排除规则的文件。此时任务应明确失败，不会触发“下载完成、自动整理已启动”。检查“光鸭离线”的允许扩展名与排除词。

### STRM 文件何时更新？

全量同步会比较远端文件 ID、etag、大小、名称和持久化索引：

- 内容/etag/大小变化：覆盖对应 `.strm`。
- 远端改名或移动：生成新镜像路径并清理旧路径。
- 远端删除：清理本地失效 `.strm`，并在通知中报告清理数量。
- 播放服务地址变化：重新执行同步会重写内容；未变化时应在跳过原因中说明。

### 局域网其它设备上的 Jellyfin 无法访问 STRM？

先分清是"连不上"还是"地址不对"——这是两个不同的问题。

**① 根本连不上（连接被拒绝 / 超时）**：最常见。Docker 默认只把服务发布到宿主机 `127.0.0.1`，其它局域网设备无法访问。

在那台设备上测一下（把 IP 换成 MediaFlux 所在机器的局域网 IP）：

```bash
curl -I http://192.168.1.20:1258/healthz
```

连不上就按你的部署方式放开监听，并确认防火墙 / 安全组放行 `1258`：

| 部署方式 | 怎么放开 |
| --- | --- |
| Docker Compose | 修改宿主机 `.env`：`MEDIAFLUX_PUBLISH_HOST=0.0.0.0`，如需换宿主机端口再修改 `WEB_PORT`，然后执行 `docker compose up -d` |
| Python 源码（仅开发调试） | 通过 `mediaflux.py start --host 0.0.0.0 --port 1258` 等启动参数配置；Web 设置页不提供网络绑定控件 |

**② 能连通、但播放仍失败**：是 `GY_STRM_BASE_URL` 填错了。它要填**局域网真实 IP**（如 `http://192.168.1.20:1258`），**不能填 `localhost` / `127.0.0.1`**——那等于让 Jellyfin 去访问它自己，必然失败。详见下一条。

### `.strm` 能扫描但播放失败？

`GY_STRM_BASE_URL` 必须从 Jellyfin/Emby 和实际播放器可访问。不要填容器自身的 `localhost`。检查：

```bash
curl -I http://MediaFlux地址:1258/healthz
```

`.strm` 内是系统生成的 `/playgy/{file_id}/{etag}/{size}/{filename}?v=1&sig=...`，不要手工修改。

### `/guangya/media-proxy` 与 `/playgy` 是一回事吗？

不是：

- `/playgy`：校验签名，获取光鸭 signedURL，返回 302，云盘流量不经过 MediaFlux 持续转发。
- 媒体代理：固定上游代理 Jellyfin/Emby 的普通 HTTP/WebSocket，并按规则改写 PlaybackInfo。未改写请求透传上游。

## Telegram

### Bot 无响应或日志显示 `api.telegram.org` 超时？

这是 MediaFlux 到 Telegram API 的网络连接超时，不是命令错误。配置网络代理并在“设置 → 网络代理”测试 Telegram。程序会压缩重复异常日志并自动重试。

### `/rss_refresh`、`/rss_dl` 为什么没有反馈？

命令会先发送“正在处理”，随后返回成功、失败或超时原因。若仍无反馈，检查 Chat ID、用户白名单、Bot Polling 状态和实时日志。

### 人工候选按钮为什么显示运行中？

候选选择会进入整理队列；点击后无需等待当前目录结束。若按钮已过期、任务已经处理或服务重启，Bot 会返回明确状态，需要重新发起确认。

## 下载与待处理

### 看板显示待处理，但找不到任务？

点击看板待处理指标进入 `/downloads` 的“待处理”页签。这里展示下载、自动整理、STRM 或媒体库刷新被中断/失败的请求。

### “清除”会删除文件吗？

不会。清除只关闭该下载请求的待处理/异常标记，使其不再计入待处理数量；不会删除 qB 任务、光鸭文件、本地媒体、STRM 或历史审计日志。

### 重新下载到“光鸭/两者”后为什么还失败？

每个目标独立执行。若资源文件被扩展名或排除词过滤，光鸭目标会失败，但 qB 仍可能成功。查看原因列，不要把“请求提交成功”误认为“所有目标下载完成”。

## 日志与工具

### `/tools` 为什么没有原来的刮削预览？

工具能力已迁移：

- 刮削实验室：`/logs#scrape`
- TMDB 映射锁：设置 → 刮削识别
- GCID：光鸭 → GCID 清单

`/tools` 现在是迁移说明和导航页。

### 如何清理整理日志？

日志中心“清理记录”可按范围清理光鸭与本地整理记录。它只删除审计记录，不删除媒体文件。
