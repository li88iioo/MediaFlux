# MediaFlux 镜像与版本发布检查清单

## 1. 发布原则

- 正式发布由推送 `v<SemVer>` tag 触发；当前 Docker 工作流未提供 `workflow_dispatch` 手动触发入口。
- Docker 镜像发布 `linux/amd64` 与 `linux/arm64` 双架构。
- GHCR 镜像使用去掉 `v` 前缀的精确版本标签（如 `1.2.0`）与 `latest`。
- 普通升级与容器重启必须保证挂载卷中的数据库、配置、Token、STRM 和整理任务数据完整保留。

## 2. 发布前检查

1. `main` 工作区干净，全量自动化测试为 0 failure / 0 error。
2. 运行 `compileall` 与诊断自检：`python -m compileall -q app` 与 `python mediaflux.py doctor`。
3. 检查 `requirements.txt` 与 `requirements-release-runtime.lock` 依赖锁一致。
4. 检查 Dockerfile 运行时依赖锁、内置 `/usr/bin/ffprobe`、权限初始化入口、默认 NAS 兼容模式与可选 PUID/PGID 降权；容器内执行 `ffprobe -version` 和 `gosu --version` 必须成功。

## 3. 发布交付物

- **GHCR 容器镜像**：
  - `ghcr.io/li88iioo/mediaflux:<SemVer-without-v>`（多架构 manifest：`linux/amd64` + `linux/arm64`）
  - `ghcr.io/li88iioo/mediaflux:latest`（稳定版自动更新）
- **版本元数据**：
  - `BUILD-INFO.json`、`RELEASE-NOTES.txt`

## 4. 镜像验收

1. 容器运行 `python mediaflux.py version --json`，确认版本号、commit hash 与 package 为 `docker`。
2. 容器启动探针：`/healthz` 与 `/readyz` 均返回 HTTP 200。
3. `doctor --json` 能正确检查环境与权限。
4. 容器挂载已有宿主机 `./db` 数据卷启动，确认历史数据完整加载且无损。
