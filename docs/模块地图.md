# MediaFlux 模块地图

本文按**业务领域**拆分 `app/` 下的全部 Python 模块，回答维护时最常见的三个问题：

1. 改这个功能，要动哪些文件？
2. 这条规则 / 默认值 / 状态的唯一来源在哪？
3. 改完要跑哪些测试？

链路时序与运行原理见 [开发文档](开发文档.md) 与 [项目全链路拓扑图](项目全链路拓扑图.md)；本文只做“功能 → 代码”的索引，不重复原理。

## 使用方式

- **找功能**：先在下方领域卡片定位领域，再看“核心文件”。只知道文件名时，查文末[全量模块索引](#附录全量模块索引)。
- **改规则前**：先看卡片的“唯一来源”。新增同类逻辑必须复用它，不得另起一套（见 `AGENTS.md`“彻底根除双轨”）。
- **选测试**：卡片给出的测试通配是该领域的最低验证范围。跨领域调用方可用下面的命令补全：

  ```bash
  grep -lE 'app\.modules\.organize_rules\b' tests/*.py   # 把模块名换成本次改动的模块
  ```

- **维护本文**：新增、删除或移动 `app/**/*.py`（`__init__.py` 除外）时，必须同步更新文末索引；卡片里引用的文件路径和测试通配也要保持存在。`tests/test_module_map.py` 会校验这三点，漏改即失败。

## 分层总览

```text
入口层   routes/*（Web 页面 + JSON API）  bot/*（Telegram）  agent/*（Media Agent）  sdk.py（脚本接口）  cli.py
           │                                  │                     │                       │
业务层   modules/*  discovery/*  indexers/*   ── 各领域服务、调度器、后台 worker
           │
数据层   repositories/*（按领域拥有表）  →  database.py（连接 / 时钟 / settings_kv）  →  SQLite（WAL）
外部系统 clients/*：光鸭、qBittorrent、TMDB、豆瓣、Jellyfin / Emby、OpenAI 兼容模型
```

约定：

- 入口层只做参数校验和协议转换，业务决策放在 `modules/`。Web、Telegram、Agent、SDK 四个入口共用同一个业务函数，不各写一份。
- 表由 `repositories/<领域>.py` 唯一写入；`app/database.py` 不再转发仓储函数，测试 patch 目标写 `app.repositories.<模块>.<函数>`。
- 后台服务统一在 `app/main.py` 的 `start_background_services()` / `stop_background_services()` 中启停，启动顺序见 D01。

## D01 应用骨架与配置

- **职责**：应用工厂、生命周期、页面路由、登录与 CSRF，配置读写、白名单开关与策略，以及配置变更后的运行时刷新。
- **入口**
  - Web：`app/routes/pages.py`（全部 HTML 页面；`/search` 全局搜索聚合在 `app/modules/global_search.py`）、`app/routes/auth.py`（`/setup`、`/login`、`/logout`）、`app/routes/api.py`（`/api/config`、连接测试、更新检查）、`app/routes/tools_api.py`（`/api/tools`：GCID、TMDB 正则、发布格式等工具页）。
  - CLI：`app/cli.py` 的 `main()` 是生产入口，最终调用 `app/main.py` 的 `run()`。
- **核心文件**
  - `app/main.py`：`create_app()` 注册路由与中间件；`start_background_services()` 按顺序启动 Agent 运行时 → 媒体刷新合并器 → 整理任务恢复 → **通知 dispatcher（必须先于所有通知生产者）** → 确认 dispatcher → STRM / RSS / 订阅 / 整理 / 本地媒体调度器 → 下载跟踪 →（Agent 开启时）复核、巡检、长任务调度器 → Telegram Bot。
  - `app/config.py`：`get` / `get_many` / `get_bool` / `get_int_clamped` / `get_int_setting`，负责 `user.env` 的原子写入与 CAS。
  - `app/modules/feature_config.py`：白名单功能开关；`reload_runtime(changed_keys, ...)` 是**所有配置变更后的唯一运行时刷新入口**。
  - `app/modules/policy_config.py`：非敏感策略白名单（`POLICY_BY_KEY`、`policy_int`）。
  - `app/modules/schedule_policy.py`：STRM、整理、巡检三类 Cron 策略的预检与原子提交。
  - `app/modules/setup_bootstrap.py` + `app/modules/first_run.py`：首次安装事务与管理员凭据落盘。
  - `app/services.py`：首页看板、库存统计、媒体服务器客户端工厂。
  - `app/web.py`：模板渲染、`require_api_login`、`api_response` / `api_error`。
- **唯一来源**
  - 布尔默认值：`app/defaults.py` 的 `DEFAULT_BOOL_CONFIG_VALUES`；整数边界：`INT_SETTING_BOUNDS`；AI 置信度：`AI_RECOGNITION_CONFIDENCE_BOUNDS`。
  - 设置页展示默认值：`app/routes/api.py` 的 `_UI_DEFAULTS`。
  - 运行目录：`app/runtime_paths.py`；敏感字段脱敏：`app/sensitive_data.py`；会话密钥：`app/modules/web_secret.py`。
- **测试**：`tests/test_config*.py tests/test_settings*.py tests/test_setup*.py tests/test_first*.py tests/test_startup*.py tests/test_web_*.py tests/test_security*.py tests/test_pages*.py`
- **坑**
  - 新增配置项不要在调用点硬编码默认值，要写进 `app/defaults.py` 或 `POLICY_BY_KEY`。
  - 改配置后必须走 `reload_runtime`，不能直接操作某个调度器。
  - `get_bool("")` 为 False：显式空值和“未设置”语义不同。
- **详解**：开发文档 §4、§6、§16、§17。

## D02 数据层

- **职责**：SQLite 连接与并发、建表声明、逐版本迁移、通用 KV 与时钟。
- **核心文件**
  - `app/database.py`：`get_conn()`、`init_db()`、`now()`（测试冻结时钟的唯一 patch 点）、`kv_get` / `kv_set` / `kv_set_conn`、`row_value`。
  - `app/database_schema.py`：全部 `CREATE TABLE` 声明。
  - `app/database_migrations.py`：版本迁移实现与登记表。
- **数据**：`settings_kv`（运行时 KV）、`task_runs`（通用后台批次记录，STRM / 整理 / 巡检 / 本地扫描共用）。其余表见各领域卡片。
- **唯一来源**：表的写入归属见各领域“数据”行；新表必须同时在 schema 和 migrations 登记。
- **测试**：`tests/test_database*.py tests/test_schema*.py tests/test_v0112*.py`，以及受影响领域的仓储测试。
- **坑**
  - 修改 schema 或迁移属于共享底层改动，验证范围要扩大到所有使用该表的领域。
  - `row_value` 对 NULL 返回默认值；需要区分 NULL 与空串的展示路径要自己处理（例如 `app/modules/global_search.py`）。
- **详解**：开发文档 §15。

## D03 识别与刮削

- **职责**：把文件名 / 目录名解析为 TMDB 作品与季集，包括规则清洗、知识库、AI 兜底、季集映射和命名模板。
- **入口**
  - Web：`app/routes/tools_api.py`（TMDB 正则、发布格式教学）、`app/routes/recognition_knowledge_api.py`。
  - 被调用方：D04 整理、D05 本地媒体、D06 下载入库、D08 RSS、D09 订阅。
- **核心文件**
  - `app/modules/scraper.py`：识别主流程（`extract_recognition_context`、`generate_query_variants`、候选打分 `Candidate` / `MatchResult`）。8k 行巨型模块，改动前先缩小范围。
  - `app/modules/recognition/`：`extractors/`（guessit、动漫、确定性三套抽取器）→ `resolver.py` → `cleaner.py`、`formats.py`（发布格式规则）。
  - `app/modules/recognition_service.py`：文件名检查与发布格式教学，Web 与 SDK 共用。
  - `app/modules/recognition_preprocess_rules.py`、`app/modules/tmdb_regex_rules.py`、`app/modules/recognition_knowledge.py`：三类用户可维护规则。
  - `app/modules/episode_mapping.py`：发布集号 → TMDB 季集的保守映射；`app/modules/episode_research_service.py`：季集研究（默认关闭）。
  - `app/modules/ai_recognition_governance.py`：AI 识别限速、并发、日预算与熔断。
  - `app/modules/naming.py`：命名模板渲染（`render_media_template`）。
  - `app/modules/nsfw.py`：番号识别与 MetaTube 客户端。
  - `app/clients/tmdb.py`、`app/clients/ai_recognition.py`、`app/clients/openai_compatible.py`。
- **数据**：`tmdb_lock`、`manual_episode_confirmations` → `app/repositories/recognition.py`；`episode_research_cache` → `app/repositories/episode_research.py`；`recognition_format_rules`、`recognition_preprocess_rules`、`recognition_knowledge`、`tmdb_regex_rules`、`media_title_aliases` 由同名模块直接维护。
- **唯一来源**：媒体身份键 `app/modules/media_identity.py`；自动识别门槛 `app/modules/recognition_policy.py`；版本共存策略 `app/modules/media_variant.py`；特别篇语义 `app/modules/special_media.py`。
- **测试**：`tests/test_recognition*.py tests/test_tmdb*.py tests/test_episode_mapping*.py tests/test_episode_research*.py tests/test_release_format*.py tests/test_nsfw*.py tests/test_anime*.py tests/test_ai_recognition*.py`
- **坑**
  - 做归一化 / 脱敏时，比较侧和展示侧要用同一规范（项目记忆“变换要同步两侧”）。
  - 豆瓣回退链失败时先检查 `DOUBAN_DBCL2` Cookie 是否过期。
- **详解**：开发文档 §8；教程 [10_发布格式教学](tutorials/10_发布格式教学.md)。

## D04 光鸭云盘与整理

- **职责**：光鸭账号与文件操作，统一整理引擎（扫描 → 识别 → 计划 → 串行写入 → 后处理），人工确认，整理日志纠偏，目录刮削，媒体规格补全。
- **入口**
  - Web：`/organize`、`/organize-rules`、`/guangya`、`/guangya/more`、`/logs`；API 为 `app/routes/guangya_api.py`（`/api/guangya`）、`app/routes/guangya_scrape_api.py`（`/api/guangya/directory-scrape`）、`app/routes/logs_api.py`（`/api/logs`，整理日志与纠偏）。
  - Telegram：`/organize`；整理确认卡片的回调。
  - 后台：`app/modules/organize_scheduler.py`（Cron）、`app/modules/organize_probe_worker.py`（规格补全）、确认 dispatcher。
  - Agent / SDK：`Cloud`、`Library` 分组。
- **核心文件**
  - 编排：`app/modules/organize_service.py`（公共入口 `preview` / `prepare_run` / `run` / `stop`）→ `app/modules/organize_tasks.py`（`OrganizeTaskManager`，`get_organize_manager()`）→ `app/modules/organize.py`（`Organizer` 协调器，7.5k 行）。
  - 阶段：`app/modules/organize_scan.py`（只读扫描）→ `app/modules/organize_runtime.py`（任务内识别 / 库存缓存）→ `app/modules/organize_groups.py`（媒体组）→ `app/modules/organize_execution.py`（`execute_organize_plans`，串行云端写入）→ `app/modules/organize_postprocess.py`。
  - 规则与结果：`app/modules/organize_rules.py`（所有入口共用的规则与自动确认判定）、`app/modules/organize_sources.py`（多源配置）、`app/modules/organize_results.py`（版本化结果协议）、`app/modules/organize_models.py`。
  - 人工环节：`app/modules/organize_confirmations.py`（TG 确认、安全重跑、识别复核调度）、`app/modules/organize_confirmation_batches.py`（Web / TG / SDK 共用的批量逐项审阅，TG 端分页展示在 `app/modules/telegram_confirmation_batch.py`）、`app/modules/organize_correction.py`（`OrganizeCorrectionService`，日志纠偏）。
  - 光鸭文件变更：`app/modules/guangya_fs_change.py`（冻结计划 + 可验证执行器，`build_fs_change_plan` / `submit_fs_change_plan`），以及基于它的 `app/modules/guangya_rename.py`、`app/modules/guangya_episode_naming.py`、`app/modules/guangya_residual_cleanup.py`、`app/modules/guangya_recycle.py`。
  - 目录刮削：`app/modules/directory_scrape.py`（`DirectoryScrapeService`）、`app/modules/directory_media.py`。
  - 规格探测：`app/modules/media_probe.py`（ffprobe 与缓存，D05 也使用）。
  - 客户端：`app/clients/guangya.py`。
- **数据**
  - `organize_log`、`organize_log_items`、`organize_operation_steps`、`organize_confirmations`、`organize_delete_audit` → `app/repositories/organize_history.py`。
  - `organize_operation_jobs` → `app/repositories/organize_operation_jobs.py`；`organize_probe_queue` → `app/repositories/organize_probe.py`；`media_probe_cache` → `app/repositories/media_probe.py`。
- **唯一来源**：光鸭写操作统一经 `cloud.change`（`guangya_fs_change`）执行，改名、清理、回收站只负责编译操作，不保存第二套计划。
- **测试**：`tests/test_organize*.py tests/test_guangya*.py tests/test_directory*.py tests/test_reorganize*.py tests/test_probe*.py`
- **坑**
  - 任何回收站调用前必须先持久化删除意图（`app/modules/organize_delete_audit.py`）。
  - 光鸭响应异常不等于服务端未提交，补偿走 `app/modules/guangya_compensation.py`。
  - 云端写入需要持有 `guangya-organize` 跨进程写锁（`app/modules/process_lock.py`）。
- **详解**：开发文档 §7、§8、§14；教程 04、05。

## D05 本地媒体整理

- **职责**：qB 下载完成或手动扫描后，把本地文件识别并安全移动到媒体库（同盘 / 跨盘事务），然后清理垃圾文件。
- **入口**
  - Web：`/local-media`，API 为 `app/routes/local_media_api.py`（`/api/local-media`：来源、任务、预览、重试）。
  - 后台：`app/modules/local_media_scheduler.py`（`LocalMediaScheduler`，由 qB 完成事件和手动扫描驱动）。
  - Agent / SDK：`Local` 分组。
- **核心文件**
  - `app/modules/local_media_service.py`：`LocalMediaService`，负责检查、识别预览、移动编排和来源配置。
  - `app/modules/local_move_transaction.py`：`LocalMoveTransaction`，安全移动事务。
  - `app/modules/local_media_tasks.py`：持久任务的查询、预览和确认重试，Web 与 SDK 共用。
  - `app/modules/local_media_candidates.py`、`app/modules/local_media_cleanup.py`、`app/modules/local_media_library.py`（媒体库绑定）。
  - `app/modules/local_storage.py`：受控扫描与快照；`app/modules/local_path_mapping.py`：qB 路径 → 本机路径。
  - `app/modules/local_media_notifications.py`：TG 通知，只显示文件名，不泄露绝对路径。
- **数据**：`local_media_sources`、`local_media_tasks`、`local_media_task_items`、`local_media_operation_steps`、`local_library_targets` → `app/repositories/local_media.py`；扫描批次复用 `task_runs`（`app/modules/local_media_scan_runs.py`）。
- **测试**：`tests/test_local_media*.py tests/test_local_move*.py tests/test_local_storage*.py tests/test_local_path*.py`
- **坑**：任务结束不等于本次归档了视频，判断结果要看 `app/modules/local_media_outcomes.py`。
- **详解**：开发文档 §9；教程 03。

## D06 下载编排

- **职责**：统一下载请求（qB / 光鸭离线 / 两者）的分发、幂等、状态跟踪与入库联动；同时负责光鸭离线规则、分享转存、GCID 导入和 qB 控制。
- **入口**
  - Web：`/downloads`、`/guangya/offline`；API 为 `app/routes/downloads_api.py`（`/api/downloads`）、`app/routes/offline_api.py`、`app/routes/share_api.py`、`app/routes/tools_api.py`（GCID）。
  - 后台：`app/modules/download_tracker.py`（`DownloadTracker`，`get_download_tracker()`）。
  - 被调用方：D08 RSS / 资源站下载、D09 订阅、D13 Agent。
- **核心文件**
  - `app/modules/download_dispatcher.py`：`dispatch_request` / `dispatch_missing_targets` / `resubmit_download_request`，负责 URL 归一化、种子解析和幂等键。
  - `app/modules/download_tracker.py`：状态跟踪，完成后联动光鸭自动入库。
  - `app/modules/download_staging_cleanup.py` + `app/modules/download_staging_reconcile.py`：隔离目录的收尾与可靠重试。
  - `app/modules/offline.py`（`submit_offline`、离线规则）、`app/modules/share_transfer.py`（分享预览与幂等转存）、`app/modules/gcid_import.py` + `app/modules/gcid_manifest.py`。
  - `app/modules/qb_control.py`：qB 写操作租约与本地整理的写入边界；`app/modules/download_diagnosis.py`：只读队列诊断。
  - `app/clients/qbittorrent.py`。
- **数据**：`download_requests`、`download_request_keys`、`download_log`、`media_download_admissions` → `app/repositories/download_requests.py`；隔离状态 → `app/repositories/download_staging.py`；`download_staging_reconcile` → `app/repositories/download_staging_reconcile.py`；`gcid_import_tasks` / `gcid_import_items` 由 `app/modules/gcid_import.py` 维护。
- **唯一来源**：下载目标取值 `app/repositories/download_requests.py` 的 `DOWNLOAD_TARGETS`。
- **测试**：`tests/test_download*.py tests/test_qb*.py tests/test_qbittorrent*.py tests/test_offline*.py tests/test_share*.py tests/test_gcid*.py tests/test_torrent*.py`
- **坑**：隔离目录收尾必须在 `guangya-organize` 写锁内执行；已确认或结果未知的删除绝不重跑。
- **详解**：开发文档 §11。

## D07 STRM、播放与媒体代理

- **职责**：根据光鸭目录生成 STRM 和伴随元数据，提供 `/playgy` 302 直链播放，运行多实例 Emby / Jellyfin HTTP 反代，并合并媒体库刷新。
- **入口**
