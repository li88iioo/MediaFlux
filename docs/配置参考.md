# 配置参考

业务配置来源优先级：**进程环境变量 > 当前运行方式的 `user.env` > 代码默认值**。Web 设置页保存到 `RuntimePaths.config_dir/user.env`；环境变量始终具有最高优先级，因此同名环境变量会覆盖页面保存值。

大部分业务配置可热加载。Docker 容器内部固定监听 `0.0.0.0:1258`；宿主机发布地址与端口分别由部署目录 `.env` 的 `MEDIAFLUX_PUBLISH_HOST`、`WEB_PORT` 控制，不在 Web 设置页修改。`WEB_SECRET_KEY`、管理员凭据等安全配置应按敏感信息管理。

布尔值接受 `1/true/yes/on`（不区分大小写），其余值视为关闭。

## 运行目录

运行目录只从显式目录环境变量、CLI `start --data-dir` 和平台默认值解析，不从 Web `user.env` 动态切换。显式目录必须是绝对路径。

| 变量 | 说明 |
| --- | --- |
| `MEDIAFLUX_DATA_DIR` | 数据根目录；数据库、光鸭 Token 和回收目录由此派生 |
| `MEDIAFLUX_CONFIG_DIR` | `user.env` 所在目录 |
| `MEDIAFLUX_CACHE_DIR` | 缓存目录 |
| `MEDIAFLUX_LOG_DIR` | 日志目录 |
| `MEDIAFLUX_STRM_DIR` | `STRM_ROOT` 未显式配置时的 STRM 运行时默认目录 |

目录解析规则：

1. 默认先使用当前运行方式的平台目录；
2. 五个 `MEDIAFLUX_*_DIR` 环境变量分别覆盖对应目录；
3. `mediaflux start --data-dir` 会覆盖数据根目录，并仅在对应专用环境变量未设置时，为配置、缓存、日志和 STRM 提供 `<data-dir>/config|cache|logs|strm-data` 默认值。

| 方式 | 数据 | 配置 | 缓存 | 日志 | STRM |
| --- | --- | --- | --- | --- | --- |
| 源码 | 项目根目录（数据库实际在 `db/mediaflux.db`） | `<repo>/db` | `<repo>/db/cache` | `<repo>/db/logs` | `<repo>/strm-data` |
| Docker | `/app/db` | `/app/db` | `/app/db/cache` | `/app/db/logs` | `/data/strm` |

源码和 Docker 保留平铺数据库、`user.env` 与光鸭 Token 布局。持久化数据建议通过 Docker volume 或宿主机目录挂载。

## qBittorrent

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `QB_URL` | 空 | WebUI 地址,如 `http://qb:8080` |

MediaFlux 对 qBittorrent v5.2.3 使用 `start` / `stop` Web API，并兼容旧版 `resume` / `pause` 回退。BTIH（十六进制或 Base32）、BTMH 和纯 BitTorrent v2 种子都会归一化为 qB 使用的 TorrentID；只有进入安全的完成上传状态后才会触发本地媒体入库，校验或移动文件期间不会提前处理。

### 本地媒体自动整理

本地媒体来源不再通过环境变量新增，请在 Web 侧栏「本地媒体」统一配置：

- 来源名称、MediaFlux 容器内下载根目录和启用状态；
- qB 所见路径前缀（可为 Windows/UNC 路径）到 MediaFlux 容器来源目录的映射；
- qB 完成触发与定时扫描独立开关、稳定等待时间和扫描间隔；
- 来源识别范围（自动、电影、剧集/动漫）；
- 默认、电影、剧集、动漫、纪录片、综艺、演唱会和儿童节目目标目录；
- 可选绑定已配置的 Jellyfin/Emby 媒体库，整理完成后按媒体库 ID 精确刷新。

目录输入框保留手动输入，同时支持登录后的服务端目录选择器。MediaFlux 仅发布 Docker 镜像，因此页面中填写的来源和媒体库目标都必须是容器内绝对路径，例如 `/media/downloads`、`/media/library`。NAS 的 NFS/SMB 共享需要先在宿主机挂载，再通过 Docker volume 映射到容器；页面不会直接接收 Windows 盘符或 UNC 路径。未配置 `LOCAL_MEDIA_BROWSE_ROOTS` 时目录选择器从容器文件系统 `/` 开始浏览；配置后只暴露明确允许的根目录，多个根目录可用逗号、分号或换行分隔。生产环境建议只配置下载目录和媒体库挂载点，以缩小可浏览范围。

从早期 Windows 源码版升级时，已有的盘符或 UNC 来源不会自动转换：请先把对应目录挂载到宿主机，再映射到 `/media/...` 容器路径并编辑来源。遗留的待处理任务会以明确的迁移提示停止，修正来源后请重新扫描或重新触发整理。旧数据库中的 SMB 账号与密码会在升级初始化时清空。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LOCAL_MEDIA_BROWSE_ROOTS` | 空（从系统文件系统入口浏览） | 本地目录选择器允许浏览的绝对路径白名单；配置后限制在指定范围内，多个路径可用逗号、分号或换行分隔 |

入库模式固定为安全移动，不提供硬链接或复制模式；来源与目标统一通过“本地整理”页面配置。

## 固定命名与媒体规格探测

整理输出不再提供模板、重命名、媒体信息补全或在线探测开关。光鸭、本地、Web、Telegram 与定时任务统一执行以下固定契约：

```text
电影目录：分类/片名 (年份) {tmdb-ID}
电影文件：片名.年份.媒体规格.ext
剧集目录：分类/剧名 (年份) {tmdb-ID}/Season N（季号不补零）
剧集文件：剧名.年份.SxxExx.媒体规格.ext
特别篇：Specials，文件使用 S00E..
```

实际文件名中的季集字段连续书写，例如 `S01E03`；媒体规格按可获得信息追加分辨率、动态范围、视频编码、帧率、音频编码和声道。旧版 `GY_ORGANIZE_RENAME`、`GY_ORGANIZE_MEDIAINFO`、`GY_ORGANIZE_MEDIA_PROBE_*`、`MEDIA_*_TEMPLATE` 与 `MEDIA_NAMING_SCOPE` 已停用：读取时不会影响整理，配置 API 也拒绝继续写入。

媒体探测固定为尽力而为：本地文件直接使用 ffprobe；光鸭文件使用实时 signedURL/直链，并复用成功的内容指纹缓存。单次探测最多 30 秒，本地预览共享 20 秒探测预算；失败只降级为文件名规格，不阻断整理。
