## 1. 项目目标与核心链路

MediaFlux 是一个自托管媒体自动化控制面。核心目标不是替代 Jellyfin/Emby 的元数据刮削器，而是保证媒体在进入媒体库前完成可靠的下载、识别、命名、分类、冲突处理和审计。

```text
资源发现 / RSS / Telegram / 手工提交
                    │
        ┌───────────┴───────────┐
        │                       │
 qBittorrent                光鸭离线任务
        │                       │
 本地媒体整理                光鸭云盘整理
        │                       │
        └──────> 统一整理规则 <─┘
                    │
       ┌────────────┴────────────┐
       │                         │
本地媒体库 + 刷新            STRM 镜像 + 刷新
       │                         │
       └──────── Jellyfin / Emby ┘
```

系统坚持以下原则：

1. 强上下文与写操作由服务端确定性约束，普通只读目标优先由受控 AI 工具循环规划。
2. 预览无副作用，正式执行才允许探测和写入。
3. 目录级写操作串行，避免同一目标竞争。
4. 失败、跳过、替换、删除和人工确认均可追踪。
5. 光鸭与本地共用识别/命名/分类规则，但使用不同存储事务。
6. STRM 以持久化索引判断新增、变化、删除与来源退役。

## 2. 技术栈与运行约束

| 项目 | 当前实现 |
| --- | --- |
| Web | FastAPI、Uvicorn、Jinja2、原生 JavaScript/CSS |
| 数据库 | SQLite + WAL，集中在 `app/database.py` |
| 调度 | 进程内调度器与互斥锁 |
| 外部服务 | 光鸭、TMDB、Jellyfin、Emby、qBittorrent、Telegram、豆瓣、Bangumi、资源站点 |
| AI | OpenAI-compatible Responses API / Chat Completions |
| 打包 | Docker（OCI 标准多架构镜像构建与发布） |
| Python | 3.12+；Docker 镜像当前使用 3.13 |

### 2.1 单 Worker 约束

必须保持一个进程、一个 Worker。以下组件是进程内单例：

- Telegram Polling。
- RSS、光鸭整理、本地整理、STRM 调度器。
- 下载跟踪器与 Agent 巡检调度器。
- 整理任务管理器和进程锁。
- 媒体代理实例管理器。

多 Worker 会导致重复调度、重复通知、Telegram 冲突和同一数据库上的竞争。

### 2.2 进程入口

`mediaflux.py` 调用 `app/cli.py`，稳定命令为：

```bash
mediaflux start [--host HOST] [--port PORT] [--data-dir DIR]
mediaflux status
mediaflux doctor [--json] [--source PATH] [--target PATH]
mediaflux version [--json]
```

## 3. 仓库目录与分层职责

```text
app/
├── agent/             # 自然语言路由、只读工具、写操作确认与会话
├── bot/               # Telegram 命令、回调、输入状态与草稿进度
├── clients/           # 外部系统协议适配器
├── discovery/         # 媒体探索 Provider、缓存与详情检索
├── indexers/          # 多站资源索引器、查询计划与运行时
├── modules/           # 业务状态机、事务、调度器与领域服务
├── routes/            # 页面路由和 JSON API
├── static/            # 页面 CSS、JS、字体和图标
├── templates/         # Jinja2 页面和弹窗
├── config.py          # 配置读取、类型转换和保存
├── database.py        # schema、迁移、DAO、恢复与索引
├── main.py            # 应用工厂、中间件与生命周期
└── services.py        # 看板、媒体服务器聚合等页面服务

packaging/             # 容器化构建元数据与发布辅助脚本
tests/                 # unittest 契约、单元、集成与页面测试
docs/                  # 用户与维护者正式文档
.superpowers/          # Agent 本地协作状态，禁止提交
```

分层规则：

- `clients/` 只处理协议和远端字段差异。
- `modules/` 保存业务规则、状态机和事务。
- `routes/` 负责鉴权、CSRF、输入校验、调用和响应转换。
- `database.py` 是持久化入口；页面脚本不得直接拼 SQL。
- `templates/static` 不应复制后端业务判断。

## 4. 应用启动与关闭生命周期

`app/main.py:create_app()` 完成中间件、静态资源、路由和 lifespan 注册。

### 4.1 启动顺序

1. 解析运行目录并创建可写目录。
2. 初始化配置和 SQLite schema/迁移。
3. 恢复中断的整理、人工确认和任务状态。
4. 启动 STRM 调度器。
5. 启动 RSS 调度器。
6. 启动光鸭整理调度器。
7. 启动本地媒体调度器。
8. 启动下载任务跟踪器。
9. 若 `AGENT_ENABLED=1`，启动下载后媒体库复核和全库巡检。
10. 启动 Telegram Bot Polling。
11. 启动已启用的媒体代理实例。

### 4.2 关闭顺序

关闭时先阻止新整理任务，再停止 Agent、下载跟踪、RSS、光鸭、本地、Telegram、媒体代理和 STRM。整理任务管理器有有限等待时间，未完成状态必须落库，下一次启动恢复为待核验而不是静默重跑。

### 5.2 功能改动的纵向检查顺序

维护一个功能时不要只改页面或单个接口，应按以下顺序检查完整链路：

1. **页面入口**：`pages.py` 是否受功能开关和登录控制。
2. **模板/脚本**：输入、空状态、加载稳定性、错误提示与移动端布局。
3. **API 边界**：参数模型、CSRF、路径/URL 校验、权限和状态码。
4. **领域服务**：幂等、串行/互斥、超时、重试、取消和部分失败。
5. **数据库**：状态是否持久化，重启后是否能恢复或明确进入待核验。
6. **通知**：Web、Telegram 和日志是否只在真实成功后发出完成消息。
7. **联动**：整理后 STRM、媒体库刷新、qB 清理是否按条件执行。
8. **测试**：至少覆盖成功、空数据、非法输入、外部超时、中断恢复和重复调用。

## 6. 认证、配置与媒体服务器

### 6.1 首次初始化与登录

- `app/routes/auth.py` 提供 `/setup`、`/login`、`/logout`。
- 未初始化源码实例默认只允许安全回环绑定；官方容器运行时默认开放一次性远程 `/setup`，管理员凭据与 Web Secret 会在初始化时安全落盘。
- Session 使用签名 Cookie、Lax SameSite 和可选 Secure。
- 状态修改接口必须通过登录与 CSRF 校验。

### 6.2 设置中心

`GET /api/config` 返回脱敏后的有效配置；`POST /api/config` 按允许键保存到 `user.env`。Secret 保存后不回传明文，前端的 `********` 表示保持原值。

设置分区：

- 控制台：管理员、端口、Jellyfin/Emby、登录壁纸。
- Telegram：Bot Token、Chat ID、授权用户、通知开关。
- Media Agent：总开关、模型协议、Base URL、模型、限流和巡检。
- 刮削识别：TMDB、匹配阈值、AI 回退、映射锁。
- 媒体探索：Provider、豆瓣/Bangumi、资源索引器。
- 下载器：qB 地址、凭据、分类和路径。
- 网络代理：代理地址、测试模式和固定目标连通性。

### 6.3 Jellyfin/Emby 客户端

`app/clients/jellyfin.py` 与 `emby.py` 封装：

- 系统信息与连接测试。
- 媒体库列表和刷新。
- 最近播放、最近入库和媒体搜索。
- 媒体图片代理和外部 ID 读取。

`app/modules/media_server_profiles.py` 统一服务器配置，供看板、本地目标选择、整理完成刷新、最近入库和 Agent 使用。

## 7. 光鸭云盘功能

### 7.1 客户端与 Token

`app/clients/guangya.py` 负责 SDK 差异和字段规范化：

- 短信流程 `init -> send -> verify -> signin`。
- Token 刷新、校验、脱敏状态和清除。
- 目录列表、创建、移动、改名、删除、分享、离线任务。
- `fileId/fileName`、`data.list`、`signedURL` 等字段兼容。
- 写操作完成后进行状态回读，不能只相信 HTTP 200。

### 7.2 目录浏览

`GET /api/guangya/dirs` 支持按目录分页/列表；前端提供列表、网格和排序。文件操作菜单根据类型决定：

- 目录：打开、刮削、自动匹配、删除。
- 媒体文件：刮削、自动匹配、删除。
- 非媒体文件：只提供删除。

直接删除调用光鸭自身删除能力，文件进入云盘回收站；MediaFlux 不另建隔离区。

### 7.3 离线转存

`app/modules/offline.py` 和 `/api/offline/*`：

1. 解析磁力、ED2K、HTTP(S) 或种子。
2. 按允许扩展名与排除词选择文件。
3. 若没有可下载文件，明确返回“解析器标记为排除”。
4. 提交到暂存目录，完成后移动到目标。
5. 暂存目录为空时安全清理。
6. 只有远端任务真实完成才进入下载跟踪和整理联动。

重复请求按下载目标独立去重；已完成请求可在待处理页重新投递尚未成功的目标。

### 7.4 分享转存与 GCID

- `share_transfer.py`：分享链接解析、短期预览令牌、选中文件恢复和请求查询。
- `gcid_manifest.py`：版本化清单导出、路径/GCID 校验和 SHA-256。
- `gcid_import.py`：导入预览、任务/项目状态、失败重试。真实私有导入能力受运行环境和能力开关保护。

## 8. 统一识别与整理引擎

### 8.1 输入发现

`directory_media.py` 递归发现视频、字幕、NFO、图片和额外目录；视频与伴随扩展名来自统一规则。目录分析需要区分：

- 同一剧集的多集文件。
- 同一电影的版本文件。
- OVA、SP、Extra 与 Specials。
- 少量无法识别的 `x.mp4` 或垃圾文件。
- 真正包含多个不同媒体的混合目录。

不能因为一个异常文件就拒绝整个可靠剧集；无法安全处理的单项进入人工确认。

### 8.2 标题预处理

处理顺序：

1. `recognition_preprocess_rules.py` 应用内置和用户规则，去发布组、站点域名、区域/字幕噪声。
2. `recognition_knowledge.py` 提供可升级的识别知识条目。
3. `naming.py`、`special_media.py` 解析标题、年份、季号、集号、OVA/SP。
4. 父目录上下文优先于单文件中的弱标题片段。
5. `tmdb_regex_rules.py` 和映射锁处理稳定的特殊来源。

知识包写入数据库时按稳定键升级，不覆盖用户自定义条目，也不要求新安装迁移旧数据。

### 8.3 TMDB、外部线索与 AI

`app/modules/scraper.py` 与 `app/clients/tmdb.py` 负责 TMDB 搜索、详情、季集范围和候选评分。

候选评估包含：

- 主标题、原始标题和别名相似度。
- 年份与媒体类型。
- 父目录和文件集的一致性。
- 季号/集号是否在 TMDB 记录范围内。
- 目录内其他文件是否支持同一候选。

外部补充：

- `recognition_hints.py` 可从豆瓣/Bangumi 获取标题线索。
- `ai_recognition.py` 只接收清洗后的有限字段，返回结构化候选。
- 外部线索和 AI 之后必须重新经过 TMDB 严格复核。

### 8.4 媒体规格

`media_variant.py` 与 `media_probe.py` 组合文件名和固定的尽力探测结果，提取：

- 分辨率、来源、编码。
- HDR/DoVi、Remux/Encode。
- 音频编码、声道和 Atmos。
- 多版本身份。

本地媒体使用文件设备号/inode（不可用时使用规范化路径）、mtime_ns 与大小作为精确版本键，直接调用本机 ffprobe。光鸭媒体使用 file_id 精确缓存，并允许相同 etag/大小的成功结果按内容指纹复用；失败缓存绝不跨 file_id 扩散，同版本成功缓存也不会被迟到失败覆盖。无副作用预览不为每个远端文件获取 signedURL，正式执行才获取实时地址并探测。缓存读写、ffprobe 缺失、网络和解析失败均 fail-open，不得阻断整理；单次探测最多 30 秒，本地预览共享 20 秒探测预算。

### 8.5 命名与分类

- 电影：`分类/片名 (年份) {tmdb-ID}/片名.年份.规格.ext`
- 剧集：`分类/剧名 (年份) {tmdb-ID}/Season N/剧名.年份.SxxExx.规格.ext`
- Specials：目录为 `Specials`，文件使用 `S00E..`。

实际字符串由 `naming.py` 按固定契约生成。电影始终使用独立 TMDB 目录；剧集必须包含 Season 目录；标准化重命名与媒体信息补全始终启用。旧版 `MEDIA_*_TEMPLATE`、`MEDIA_NAMING_SCOPE` 与 `GY_ORGANIZE_RENAME/MEDIAINFO/MEDIA_PROBE_*` 不再参与规则构造，配置 API 明确拒绝写入，避免不同入口生成不一致路径。

### 8.6 冲突与多版本

`organize.py` 和 `media_variant.py` 判断媒体身份和版本：

- 跳过、覆盖、大文件优先、质量优先等策略。
- 同季同集先比较身份，不能因文件名差异创建 `(1)` 目录。
- 更优版本替换时先保留事务恢复能力，再按配置移入回收站。
- 可选保留 DoVi/标准、Atmos/非 Atmos、Remux/Encode 等明确版本。
- `.backup-*` 只用于事务恢复，成功提交后不应遗留。

### 8.7 人工确认

`organize_confirmations.py` 持久化候选、目录指纹、状态、过期时间和 Telegram 消息关联：

- 低置信度、范围越界、媒体冲突进入确认队列。
- Bot 候选按钮显示片名、年份、评分以及实际季号。
- 点击候选只入队，不阻塞用户选择其他媒体。
- 服务重启后可恢复未完成确认；过期按钮安全失败。

### 8.8 NSFW

`nsfw.py` 仅在开关启用且文件名/父目录含高置信度番号时调用自建 MetaTube：

- 先去常见域名和发布噪声。
- 使用独立成人分类目录。
- 普通媒体不会送入 MetaTube。
- Token、Endpoint 和超时均由配置控制。

## 9. 本地媒体整理

### 9.1 配置模型

`local_media_sources` 保存来源根目录、qB 路径前缀、稳定等待、扫描周期和开关；`local_library_targets` 保存默认/电影/剧集/动漫目标及可选媒体库绑定。

### 9.2 目录浏览

`local_directory_browser.py`：

- 只允许绝对路径。
- 受 `LOCAL_MEDIA_BROWSE_ROOTS` 限制。
- 拒绝路径穿越和越界符号链接。
- API 返回可继续浏览的目录，而不是要求用户手输所有路径。

### 9.3 手动链路

`/api/local-media/inspect -> search -> preview -> execute`：

1. `inspect` 只读扫描并返回媒体组和垃圾候选。
2. `search` 查询 TMDB 候选。
3. `preview` 生成目标路径、冲突和移动计划。
4. `execute` 创建持久化任务并执行安全移动。

### 9.4 移动事务

`local_move_transaction.py`：

- 同文件系统使用原子替换/移动。
- 跨文件系统复制到目标临时文件，校验大小与状态后提交。
- 提交成功才删除源文件。
- 中断时保留可判定的事务状态，避免两边都丢失。

### 9.5 清理与 qB 联动

`local_media_cleanup.py` 只删除高置信度垃圾和空目录。任务失败、部分执行或有待确认项时保留现场。来源根目录受保护。

qB 联动通过 `local_path_mapping.py` 转换容器路径；完成下载触发时先等待文件稳定，再进入本地任务队列。是否清理 qB 历史由独立生命周期配置决定，不与媒体文件删除混为一谈。

## 10. STRM、302 播放与媒体代理

### 10.1 STRM 同步

`strm.py` 负责扫描和镜像，`scheduler.py` 负责任务编排：

- 多来源全量/增量扫描。
- 目录级缓存、批量读取和有限并发。
- 生成 `.strm` 与可选 NFO/图片元数据。
- 持久化 `strm_index`。
- 识别远端改名、移动、etag/大小变化和删除。
- 清理失效 STRM 与空目录。
- 来源移除时进入 `strm_retired_sources`，按原根目录安全退役。
- 失败写入 `strm_failures`，支持按动作精确重试和进度通知。

整理联动与 `/api/strm/run/fast` 只处理可信变化队列；兼容入口 `/api/strm/run`、`/api/strm/run/full`、`/sync_gy` 和 Cron 执行配置来源的并发完整扫描。

### 10.2 `/playgy` 302

`.strm` 内容由 `playgy_signing.py` 生成：

```text
/playgy/{file_id}/{etag}/{size}/{filename}?v=1&sig=...
```

播放时：

1. 校验版本、签名、file ID、etag、大小和文件名。
2. 使用光鸭客户端获取当前 signedURL。
3. 返回 302；视频数据不持续经过 MediaFlux。
4. signedURL 和 Token 不写入普通日志。

### 10.3 媒体代理

`media_proxy.py` 是独立的固定上游代理：

- 普通 HTTP 与 WebSocket 透传 Jellyfin/Emby。
- 维护多个代理实例、端口冲突检测和配置热加载。
- 可按 Item ID/MediaSourceId 记录绑定并改写 PlaybackInfo。
- 本地媒体和未命中绑定的请求继续透传媒体服务器。
- 播放记录落库，用于审计和 UI 展示。

它与 `/playgy` 不同：前者代理媒体服务器请求，后者只为光鸭 STRM 获取直链并 302。

## 11. RSS、资源索引与下载编排

### 11.1 RSS

`rss.py`、`rss_scheduler.py` 和 `rss_api.py`：

- 订阅增删改查、手动刷新和自动开关。
- 条目去重、状态、标签和过滤规则。
- 单条/批量下载与标记。
- 刷新互斥，避免手动和定时重复拉取。
- Telegram `/rss_refresh`、`/rss_dl` 提供开始、完成和失败反馈。

### 11.2 媒体探索

`app/discovery/` 聚合公共豆瓣等 Provider：

- 分区、榜单、筛选、搜索和详情。
- 缓存、stale 回退、图片代理和错误隔离。
- 外部 ID 映射到本地 Jellyfin/Emby。
- 收藏列表。

### 11.3 多站资源索引

`app/indexers/` 与 `indexers_api.py`：

- 站点注册、启用开关、超时、并发和速率限制。
- 搜索查询计划和站点级失败原因。
- 结果按发布时间、集号等字段排序。
- 标签点击筛选站点结果。
- 单条或批量推送到 qB、光鸭或两者。

站点实现必须失败隔离；一个站点超时不能拖死整次搜索。

### 11.4 下载请求状态机

`download_dispatcher.py` 统一 Web、RSS、Telegram、Agent 的提交：

- qB 与光鸭分别记录目标状态。
- 同一资源重复提交只补投失败/缺失目标。
- 解析失败、过滤排除、提交失败、跟踪中断、整理失败、STRM 失败分别记录。
- `/downloads` 待处理可重投到单目标/两者，或清除异常标记。
- 清除只改变待处理状态，不删除远端/本地文件。

`download_tracker.py` 只有在下载真实完成后才触发整理、STRM 和媒体库刷新。

## 12. Telegram Bot

`app/bot/handlers.py` 注册命令、消息和回调。主要命令：

- `/start`
- `/sync_gy`（完整扫描并校准）
- `/organize_gy`
- `/media_search 片名`、`/媒体搜索 片名`
- `/rss`、`/rss_refresh ID`、`/rss_dl ID`
- `/status`
- `/agent`（始终保留在菜单，用于查看状态与热切换 Agent）
- `/agent_reset`（仅在 Agent 启用时显示）

普通输入：

- 磁力、ED2K、HTTP(S)、种子和光鸭分享链接优先进入下载/转存流程。
- 其他文本在 Agent 开启且授权通过时进入 Agent。
- 未识别或异常资源必须返回原因，不能静默处理。

交互体验：

- 长操作发送 `typing`/阶段状态。
- 优先使用富草稿，降级为文本草稿或 `editMessageText`。
- 同一剧集按季汇总入库结果、规格、大小、总集数和缺集。
- 人工候选使用 Inline Keyboard，回调幂等并可排队。
- 群组命令按 `TG_CHAT_ID` 和授权用户白名单双重检查。

## 13. Media Agent

### 13.1 功能门控

`agent/feature_gate.py` 统一 `AGENT_ENABLED`：关闭后隐藏页面、拒绝 Agent API、停止 Telegram Agent、下载后复核和全库巡检，但保留配置与历史。

### 13.2 编排顺序

`agent/orchestrator.py` 与 `service.py`：

1. 输入安全、凭据检测与 owner-scoped 会话绑定。
2. 配置/RSS 续句、候选资源、最近巡检和已验证媒体身份等强上下文确定性短路。
3. 普通只读请求优先进入受注册表约束的 LLM 原生工具循环；Provider 不可用或选择不可靠时回退确定性 handler。
4. 只读候选根据工具名称、描述、参数和服务端示例做有界语义排序；高成本全库能力仍要求明确范围。
5. 明确动作继续走确定性业务解析；模型可见的确认型工具也只能生成 prepare 结果。
6. 用户使用一次性票据确认后，服务端才执行动作。

### 13.3 生产诊断与可观测性

- `python tools/agent_doctor.py` 执行离线、只读诊断；`--json` 输出稳定结构，检查 Agent/Provider 静态配置、SQLite `quick_check` 与必需表、Web Secret 权限、独立抓取密钥和工具注册表。命令不会联网，也不会回显密钥值。
- `/api/agent/metrics?format=prometheus` 默认要求登录；配置至少 24 位的 `AGENT_METRICS_SCRAPE_KEY` 后，监控系统可使用独立 Bearer Key 抓取。该 Key 不会授权其他 Agent API。
- 指标按低基数协议、模型和结果聚合 LLM 请求，并记录回合数、LLM/工具耗时、Token 用量与 SQLite 争用；确认票据的 `discarded` 等生命周期事件继续独立计数。

### 13.4 工具域

Agent 工具覆盖：

- 系统/工作区概览和下一步建议。
- 媒体服务器、最近入库和缺集检查。
- RSS 状态、刷新、下载和重试。
- 下载诊断和最近提交。
- 光鸭/本地整理状态与配置解释。
- STRM 失败诊断和精确重试。
- 资源搜索与下载候选。
- 配置诊断、只读说明和受控修改。
- Tavily 网页搜索（可选）。

### 13.5 LLM 边界

- 支持 `auto`、`responses`、`chat_completions`、`anthropic_messages`。
- Base URL 规范化到 `/v1`，模型列表来自 `/models`。
- 只发送当前必要消息与脱敏、有限会话摘要；工具原始结果必须先经过公开投影。
- 原生只读循环最多暴露 14 个语义候选、执行 5 个工具轮次/8 次工具调用，并共享最多 6 次 Provider 请求预算；最后一次请求不得继续执行工具。
- 限流、超时、重复调用、无效 JSON 或 Provider 失败时安全回退，并保留已完成工具的部分结果。
- 提示词和 `llm_examples` 只帮助理解与排序；真正权限由工具白名单、风险等级、参数校验、鉴权和确认令牌控制。

| `agent_*` | Agent 动作、会话、消息、巡检、通知 outbox 与额度 |
| `media_proxy_*` | 代理实例、绑定与播放记录 |

数据库初始化必须保持幂等。新增字段使用向前兼容迁移；新表必须有查询路径需要的索引。不要在启动时执行不可逆批量数据改写。

## 16. 配置加载、运行目录与热更新

### 16.1 优先级

配置来自环境变量和运行配置目录的 `user.env`。明确的进程环境通常优先；Web 只保存允许键。

`start --data-dir DIR` 会设置：

- `MEDIAFLUX_DATA_DIR=DIR`
- 未显式设置时派生 `config/`、`cache/`、`logs/`、`strm-data/`

### 16.2 各平台目录

| 方式 | 配置 | 数据 | 缓存/日志 | STRM |
| --- | --- | --- | --- | --- |
| 源码 | `db/user.env` | `db/mediaflux.db` | `db/cache`、`db/logs` | `strm-data` |
| Docker | `/app/db/user.env` | `/app/db/mediaflux.db` | `/app/db/cache`、`/app/db/logs` | `/data/strm` |

### 16.3 热更新

可热更新：大多数业务设置、Telegram Token、整理规则、STRM 计划、RSS、Agent 和媒体代理实例。

需重启：`WEB_SECRET_KEY`、实际进程监听地址/端口、容器端口映射等启动级项目。

## 17. 安全边界

- 所有写 API 需要登录和 CSRF。
- Secret 只写不回显，日志统一脱敏。
- 文件路径必须规范化并限制根目录，拒绝 `..`、符号链接越界和路径穿越。
- 外部 URL 需要协议、主机和 SSRF 限制。
- Telegram 群组使用 Chat ID + 用户白名单。
- Agent 写动作使用短期确认令牌和幂等检查。
- `/playgy` 使用 HMAC 签名，不接受未签名 file ID。
- 分享预览令牌短期有效，不能信任客户端提交的任意文件 ID。
- Docker 使用非 root、drop capabilities、no-new-privileges。

## 18. 容器化构建与发布架构

### 18.1 Docker 构建

- `Dockerfile`：使用官方 Python slim 运行时，锁定 `requirements-release-runtime.lock`，内置 `/usr/bin/ffprobe` 与 `gosu`。入口只初始化 MediaFlux 自有目录；家庭/NAS 默认保持容器 root 访问显式挂载目录，需要时可通过 `MEDIAFLUX_RUN_AS_ROOT=0` 与 PUID/PGID 降权。
- `docker-compose.yml`：提供标准化的单机编排模版，支持数据卷持久化挂载与环境变量注入。

### 18.2 发布工作流

- `.github/workflows/docker.yml`：监听 tag 与 main 分支推送，自动构建并发布 `linux/amd64` 与 `linux/arm64` 多架构 Docker 镜像到 GitHub Container Registry (`ghcr.io`)。

## 20. 常见扩展方式

### 20.1 新增配置项

1. 在对应模块给出安全默认值。
2. 加入 `api.py` 允许读取/保存集合。
3. 页面展示当前有效值，Secret 使用保留占位。
4. 明确热更新还是重启。
5. 添加保存、默认值和真实消费路径测试。

### 20.2 新增资源站点

1. 在 `app/indexers/` 实现 Provider。
2. 注册站点 ID、能力、超时和限流。
3. 返回统一资源模型和明确失败原因。
4. 添加查询计划、解析器、缓存和 UI 筛选测试。

### 20.3 新增整理规则

1. 预处理只做可解释的标题转换。
2. 不把画质/集号误当标题。
3. 目录上下文和文件集一致性必须参与测试。
4. 先增加刮削实验室预览，再进入自动写入。
5. 为电影、剧集、多季、OVA、混合目录和冲突增加回归。

### 20.4 新增后台任务

1. 提供单例、启动、停止和状态。
2. 持久化运行结果或失败状态。
3. 支持幂等、限流和重启恢复。
4. 接入 lifespan，补充关闭测试。
5. 禁止依赖多 Worker。

### 20.5 新增 Agent 写工具

1. 强上下文对象仍由确定性解析器绑定；普通只读能力可声明 `llm_read` 与无敏感信息的 `llm_examples`。
2. 写动作必须拆成 prepare/confirm，且不得加入原生只读执行面。
3. 校验主体、权限、参数和过期时间。
4. 写入动作历史，返回可解释结果。
5. Telegram/Web 分别测试会话隔离。
