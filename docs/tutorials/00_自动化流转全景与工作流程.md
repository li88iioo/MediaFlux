# 进阶实战：MediaFlux 自动化流转全景与工作流程

MediaFlux 将原本割裂的下载、离线转存、TMDB 识别刮削、本地/云盘文件整理、STRM 直连生成、媒体库刷新与通知推送串联为一条自动化且安全可控的流水线。

## 2. 各阶段执行机制详解

### 阶段一：任务接入与触发 (Ingress)
- **RSS 自动订阅**：定时轮询 Mikan（蜜柑计划）等番剧 RSS 订阅源，支持按字幕组、画质、黑白名单过滤，自动提取磁力并下发下载。
- **Telegram Bot 交互**：随时在手机端向 Bot 发送磁力链接、种子文件或网盘分享链接，Bot 自动解析并创建下载或转存任务。
- **Web 控制台手动添加**：在 Web 界面「任务管理」或「媒体探索」页一键推送下载。

### 阶段二：下载与离线调度 (Downloader)
- **本地 qBittorrent**：下发种子到本地 qB 下载器，自动打上分类标签并实时监听下载进度与做种状态。
- **光鸭云盘离线转存**：针对网盘资源直接调用云盘 API 进行秒传、离线下载或分享转存，不消耗本地硬盘空间。

### 阶段三：TMDB 智能识别与刮削 (Scraper & Matcher)
- **标题清洗与特征提取**：自动剥离字幕组前缀、分辨率（1080p/4K）、编码格式（x265/HEVC）及无用广告标识。
- **精准匹配算法**：结合中文/英文标题、发行年份、拼音比对，精准匹配 TMDB 条目，自动识别剧集分季与特别篇（`Specials`/`S00E##`）。
- **映射锁与待确认机制**：置信度较低的文件自动进入人工确认列表；对特殊命名的番剧可一次性设定「映射锁」，后续集数永久自动精准识别。

### 阶段四：安全整理与分类归档 (Organizer)
- **本地整理（事务性移动）**：
  - 同一磁盘执行原子重命名（`os.rename`），毫秒级完成。
  - 跨磁盘/文件系统采用事务保障机制：先写入目标临时文件 → 校验完整性 → 确认入库 → 安全清理源文件。
  - 垃圾文件安全清理：仅删除无用的 sample 样片与广告文本，外挂字幕与特效字体完整保留。
- **网盘归档**：
  - 在光鸭云盘远端自动创建标准影视目录树并重命名。
  - 提供防冲突保护与无副作用预览，杜绝误覆盖已有文件。

### 阶段五：STRM 增量生成与 302 直链 (STRM Engine)
- **SQLite 增量索引**：本地 SQLite 数据库精确记录云盘文件映射关系，仅对新增或变动的文件生成/更新 `.strm`。
- **防误删熔断保护**：当云盘接口偶发网络异常或返回为空时，自动触发安全熔断，坚决防止清空本地 STRM 媒体库。
- **302 直链秒级播放**：播放器读取 `.strm` 文件发起请求，MediaFlux 校验并秒级 302 重定向到云盘 CDN 直链，服务端零转码、零出口流量消耗。

### 阶段六：媒体库刷新与通知 (Sync & Egress)
- **Jellyfin / Emby 自动刷新**：整理完成后通过 API 自动通知媒体服务器扫描对应媒体库路径，实现新片秒级入库上架。
- **Telegram 实时推送**：入库成功后向 Telegram 发送富文本通知，附带海报封面、影视标题、季集数及整理详情。
