# 进阶实战：性能调优与大规模媒体库（万级文件）优化指南

当影视库规模达到数万部电影、十万集电视剧或海量动漫时，合理的数据库索引、I/O 调度与缓存配置将极大提升 MediaFlux 与媒体服务器的响应速度。

---

## 1. 架构级性能优势剖析

MediaFlux 在底层架构上为高性能与低资源占用做了深度工程优化：

- **单 Worker 协程驱动（FastAPI + Uvicorn + uvloop）**：轻量内存占用（日常仅 30MB~60MB RAM），单机轻松支持 500+ 并发 302 重定向。
- **SQLite WAL 模式与专用只读事务**：Write-Ahead Logging 机制实现“读写并发互不阻塞”，索引查询毫秒级响应。
- **增量防误删哈希缓存**：STRM 增量同步只对远端变动条目计算写入，万级条目扫描耗时仅需数十秒。

---

## 2. SQLite 数据库性能调优

MediaFlux 数据库默认位于数据目录下的 `mediaflux.db`。针对超大规模媒体库，可进行如下优化：

### 2.1 确认 WAL 模式已启用
在终端或 Python 中执行只读检查：
```bash
python3 -c "import sqlite3; conn=sqlite3.connect('db/mediaflux.db'); print('Journal mode:', conn.execute('PRAGMA journal_mode;').fetchone()[0])"
```
正常输出应为 `wal`。

### 2.2 定期执行数据库整理与碎片压缩
随着数千次整理与 STRM 增删，定期执行 `VACUUM` 可减小数据库体积并提升索引缓存命中率：
```bash
python3 -c "import sqlite3; conn=sqlite3.connect('db/mediaflux.db'); conn.execute('VACUUM;'); conn.execute('PRAGMA optimize;'); print('DB Optimized!')"
```

---

## 3. STRM 增量同步与网络 I/O 调优

1. **增量 Cron 时间间隔**：
   - 建议设置为每天凌晨低峰期同步一次（如 `0 4 * * *`）。
   - 避免设置过于频繁（如每 5 分钟），以保护云盘 API 额度与减少磁盘 I/O。
2. **多源目录层级扁平化**：
   - 在光鸭云盘中建立清晰的一级影视分类（如 `/影视库/电影`、`/影视库/剧集`、`/影视库/动漫`），避免将网盘根目录作为单一源目录进行深度递归扫描。

---

## 4. 低功耗 NAS 节能与休眠优化

如果 MediaFlux 部署在配备机械硬盘的家庭 NAS（如群晖、威联通、TrueNAS）上：
- **将 `db/` 目录置于 NVMe SSD**：数据库读写完全在 SSD 完成，不会唤醒机械硬盘阵列。
- **STRM 目录占用极低**：单部电影 `.strm` 文件仅几十字节，一万部电影占用磁盘不到 2MB，几乎无 I/O 开销。
